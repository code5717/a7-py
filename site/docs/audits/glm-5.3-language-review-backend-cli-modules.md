## New defects

1. **CRITICAL — generic struct fields that wrap `$T` fail codegen (exit 7).** `Box($T) :: struct { items: []$T }` collects `T` as generic (zig.py:538-542) and is emitted as a type function, but field emission goes through `_emit_type_node_generic` (zig.py:590-597), which only handles a bare `TYPE_GENERIC` and calls `_emit_type_node` with an empty `generic_env` for anything else → `_type_contains_generic` trips the guard at zig.py:2076-2077 ("generic type requires an explicit generic environment"); `ref $T` fields hit zig.py:2085-2091. Expected: `fn Box(comptime T: type) type { return struct { items: []T, ... } }`. Actual: CodegenError. Only bare `value: $T` fields work.
2. **HIGH — hoisted nested functions: duplicate names and free variables.** Two top-level functions each containing `helper` both emit `fn helper(...)` at module level (zig.py:427-437, no renaming) → duplicate definition. A nested function referencing an enclosing local/parameter is hoisted veriantum with no capture analysis → undeclared identifier in Zig. Snippet: `main :: fn() { x := 1; double :: fn(v: i32) i32 { return v + x } }`.
3. **HIGH — file-module calls bypass type and safety checking entirely.** For `file_module_call` nodes the type checker visits args and returns UNKNOWN with no arity, arg-type, ref-argument, or generic checks (type_checker.py:1340-1343); the backend emitter (zig.py:1701-1705) also ignores `implicit_ref_args`, so a `ref` parameter never gets its `&`. Wrong arity or ref-args to imported functions pass A7 (exit 0) and fail at Zig.
4. **MEDIUM — module non-function declarations get no prefix and no collision check.** compile.py:783-788 prefixes only FUNCTION. Two imported modules declaring `Point` emit two `const Point`; a module `var`/`const` colliding with a main-module name likewise. Also `_module_emit_prefix` (compile.py:607-609) maps `lib/a` and `lib_a` to the same `module_lib_a__` prefix.
5. **MEDIUM — default value for `[N]string` is invalid Zig.** `var a: [2]string;` (no initializer) lowers through `_default_value` → `[_][]const u8{0} ** 2` (zig.py:2201-2205 with `_default_value_for_elem` returning `"0"` for strings, :2211-2219) — type error: comptime_int where `[]const u8` expected.
6. **MEDIUM — declaration-site keyword mismatch** (see item 16 above): quoting exists only at reference sites; keyword-named functions/structs/fields/variants/captures emit invalid or mismatched Zig.
7. **LOW — output path derivation rewrites directory components.** `_generate_output_path` uses `input_path.replace(".a7", ext)` (compile.py:1018-1020), replacing the *first* occurrence anywhere: `x.a7dir/prog.a7` → `x.zigdir/prog.zig`. `Path.with_suffix` is used correctly everywhere else (compile.py:1003, cli.py:85).
8. **LOW — match-capture bindings bypass scope/rename machinery.** `_visit_match_as_if_chain` emits `const {name} = {scrutinee};` with raw name, no `_declare_var_in_scope`, no quoting (zig.py:1267-1276) → shadowing and keyword captures break.
9. **LOW — `defer` of unhandled statement kinds lowers to `defer void;`.** `_emit_statement_inline` returns `"void"` for VAR/IF/RETURN/etc. (zig.py:2438-2451) → invalid Zig; known-accepted gap per the comment at safety.py:70-74, listed here for completeness.
10. **LOW — `main` signature never validated.** With io, the wrapper hand-writes `__a7_user_main();` (zig.py:181-184), discarding a non-void return → Zig "value ignored"; without io, `pub fn main() i32` is not a legal Zig entry. Extension of the no-`main`-check family (LNG-16).
11. **LOW — `~1200`-line function bodies and any >1000-declaration program hit the iteration cap silently** (parser.py:171-228): success-shaped exit 0 with truncated declarations plus a stdout warning that corrupts JSON (overlaps item 21; the truncation itself is the new part).

## Design questions (no defect claimed)

- Shift-amount and integer-overflow obligations: intentionally deferred (safety.py:796-801 comment) but undocumented against ReleaseFast.
