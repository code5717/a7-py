# L67 public-input benchmark promotion

Four rewritten workloads now belong to the host-regression suite:
`mem_cache`, `mem_copy`, `mem_text` and `mem_cyclic`. Their source bytes match
those tested against frozen compiler source `04c5e959`. The harness sends
`A\n` and requires exact stdout plus empty stderr before accepting a sample.
The existing thirteen workloads retain their stdin behavior.

| Workload | Original iterations | Exact stdout for A |
| --- | ---: | --- |

| `mem_copy` | 50,000,000 | `result: 942376503\n` |
| `mem_text` | 1,000,000 | `result: 98811553\n` |
| `mem_cyclic` | 30,000,000 | `result: 757942091\n` |

The independent numerical models preceded execution. The
[native audit](../../tmp/v1-completion-2026-10-16/l67-native-independent-review/REPORT.md)
verified 24 exact outputs across Debug, ReleaseSafe and ReleaseFast with both
A and B inputs at these counts. The
[optimized inspection](../../tmp/v1-completion-2026-10-16/l67-retention-review/INSPECTION-RESULT.md)
traced workload heap requests, payload operations, loop bounds and successful
release paths in all eight optimized binaries. Static inspection does not
measure dynamic allocation counts, every failure path or memory costs.

The [actual harness review](../../tmp/v1-completion-2026-10-16/l67-promotion-candidate/native-smoke/ACTUAL-REVIEW.md)
verified four full-count ReleaseFast runs through the candidate's real
`emit_zig`, `build_binary` and `time_binary` helpers. Owner session 61021
terminated with exit 0. Its record contains 16 commands, 32 streams, eight
artifacts and 1,713 unchanged source files. Results identity:
`1e8564f29347478413b69b1ebcbfb297546a8f761776c8f8927c3de18e77c009`.
These one-sample durations do not qualify performance.

Revision 3 passed 45 focused tests before integration. Controlled child programs
verify input bytes, wrong numeric output, zero-exit input failure text, stderr
and nonzero exits. Replaced timers and build boundaries in pin-contract tests
do not establish A7 native behavior. Integration also extends the permanent
benchmark corpus tuple to cover all 17 sources. The
[integration record](../../tmp/v1-completion-2026-10-16/l67-live-integration/REPORT.md)
records checks of the actual live files and preserved prior bytes.

The unchanged `cx89` pin lacks seven entries. The real strict gate exited 1
before building, as required for an incomplete pin. No calibration occurred;
seven default samples, five-sample minimum, CV limit 0.10, CPU affinity and
host-regression ratio 1.15 remain unchanged. L38 separately requires reviewed
C-relative runtime and peak-live-memory limits of 1.10 per workload.

Cache uses three named slots. Text processes a buffer without retained parser
output. The integer-edge cycle has no reference-cycle ownership. All four use
explicit `new` and `del`; this promotion selects no automatic-memory mechanism.
Optimized builds use `smp_allocator`, while Debug uses `page_allocator`.
Allocation and input failures were not injected into these native A7 runs.

Independent built-in review verified the evidence and identified the missing
corpus-tuple integration, which the controller corrected. External GLM review
remains unavailable because OpenCode cannot write its log path. No new full
release-wrapper pass, idle-host performance or V1 acceptance is claimed.
