# Goose research for A7

Research date: 2026-10-17. Goose revision:
f6d31d0ef402dcbdc439d9abe50cebe37e5edd93.

Goose is worth studying for its combination of lifetime inference, compact
representations and destination-aware construction. The recommendation is to
evaluate that combination through A7's Zig backend, with explicit compatibility
and measurement gates. The user requested preparation and deep research.
C export is deferred. No new A7 syntax or production memory mechanism is selected.

The [preparation packet](../packets/P-GOOSE-direction.md) defines the proposed
experiments and decision boundaries. Current work status stays in
[STATUS](../../STATUS.md) and the [delivery roadmap](../delivery-roadmap.md).

## What was checked

## The requested features, with their conditions

| Requested outcome | What Goose actually requires | A7 preparation |
| --- | --- | --- |
| Faster execution and lower memory use | Workload-specific representations and measured compiler/runtime behavior | Keep L38's equivalent C baselines and per-workload limits; measure rather than inherit a speed claim |
| Data-stack memory without general-purpose allocation for ordinary values | Nested lifetimes and compiler-assigned regions; runtime services still allocate | Add a data-stack candidate to the memory comparison; define what the no-allocator claim covers |
| References survive growth | A growable value remains at the top of its assigned stack | Prove placement, roots and aliases; specify shrink, replacement and reuse separately |
| No lifetime annotations | Inferred roots, restricted storage/escape rules and specialization | Develop explicit internal proof obligations while preserving current source syntax |
| Nested variable data stays inline | Sizes become fixed after construction; variable-size arrays are sequential | Evaluate a separate compact representation with explicit indexing/copy costs |
| ADTs occupy the active variant's size | Variable mode restricts variant replacement and direct indexing | Preserve current tagged unions; propose compact mode separately |
| Narrow relative links and loadable images | Bounded offsets, compatible roots and structural validation | Define an explicit versioned image format and iterative verifier |
| Construction in final storage | Fresh destinations and defined exceptions for relocation, capacity and existing values | Specify a destination-passing contract before claiming zero-copy |
| Returns across multiple calls | Statically known targets, hidden control tags and normal epilogues | Retain Result and defer; decide any nonlocal control separately |
| Workers do not share mutable language values | Copied globals, transferable flat payloads and runtime-managed queues | Reconcile isolation with structured task lifetimes and bounded channels |

## Data stacks solve a constrained ownership problem

A data stack reserves an address range and advances a top pointer. Releasing a
scope restores a saved top. Two independently growing values cannot share the
same live top region. Pending returns and partially built values also occupy
destinations that stack assignment must account for.

The pinned implementation reserves the compiler-counted stacks at startup.
Hidden stack-base arguments connect calls to those regions. These facts are
compatible: a hidden argument does not imply an unbounded dynamic stack count.
The runtime defaults include a 2 GiB reservation per region, a guard gap and
platform-specific reservation/commit handling. These sizes describe address
space, not resident memory. Reservation retries can reduce a region's actual
capacity; later physical-memory commitment is a separate failure point.
Restoring a top pointer does not itself decommit the pages already touched. See [frame lowering](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/src/codegen_frames.h),
[runtime startup](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/src/runtime/runtime.h) and
[platform memory handling](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/src/runtime/runtime_impl.h).

For A7, the difficult work is proving which storage survives each call, branch,
container update and cleanup. A bump allocator alone supplies none of those
proofs. The existing safety analysis provides useful allocation and alias facts,
but does not establish a complete region-ownership system.

Goose's reusable pools permit a stale reference to observe a later occupant of
the same typed slot. That preserves a narrower memory-safety property while
allowing stale identity. A7 already rejects use of deleted allocations through
aliases under L74. Reusing an address must not silently restore a deleted A7
allocation's identity. See the [root/shrink analysis](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/src/typecheck_flow.h)
and the [specification's reuse rules](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/docs/goose_spec.md#94-type-safe-reuse-and-stale-references).

Independently growing and closing objects are a decisive workload. Goose's own
[open-document study](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/docs/design/owning_dynamic_data.md) explains slice
pools and their costs; independent dynamic stacks and opaque owning resources
remain future extensions there. A7 should test interleaved document/server
lifetimes, retained parser text, graphs and churn, not only nested scratch
scopes. This supplements the existing memory workloads rather than replacing
their ownership requirements.

The user-facing objective should be no manual memory management for ordinary
A7 data. Whether that needs only static regions, reusable pools or runtime help
is still a measured design decision. L37 permits runtime help; this research
does not revoke it.

## Compact layout trades indexing and mutation for density

Goose distinguishes fixed-size, construction-sized and resizable values.
Variable-size records can contain their bytes inline. An array of such records
cannot calculate element i as base plus i times a constant stride. It needs
sequential traversal or an index whose memory and maintenance cost must count.

Variable-mode ADTs likewise avoid padding every value to the largest variant.
That representation does not support arbitrary in-place changes to a larger
variant while keeping adjacent values and payload references intact. A7 must
state which updates are legal, and how replacement affects references.

Relative links can make a complete image position independent. The generated
verifier checks framing, element boundaries and typed links before exposing
values. Validation is more than checking that an offset falls inside a buffer.
A7 would also need overflow-safe size arithmetic, bounded work, canonical
encoding, schema/version rules and an iterative traversal for cycles.
Structural validity does not establish application invariants. See
[generated layouts and verification](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/src/codegen_types.h),
[serialization design](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/docs/design/serialization.md) and
[malformed-image fixtures](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/test/storage/serialize.goose).

For CPU AI, compact storage is not automatically the best compute layout.
Dense numeric arrays, alignment and vectorization need separate controls.
Retain existing fixed layouts and evaluate compact forms explicitly. Include
the cost of converting compact records into kernel inputs.

## Construction, functions and errors need distinct decisions

Goose forwards fresh nonfixed results into a receiving destination. Its code
also contains relocation/copy paths, and its specification qualifies
returned-local, limited-capacity and existing-value cases. “Built in place”
must name which operations carry that guarantee. See
[construction lowering](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/src/codegen_construct.h),
[call lowering](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/src/codegen_calls.h) and
[the named-initializer fixture](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/test/codegen/named_init_inplace.goose).

A7 should make the destination explicit in typed lowering, including the
initialization frontier and failure cleanup. Preserve evaluation order and
explicit copy semantics. Test aliasing between input and destination, partial
construction, selected branches and returned values. A fixed-record success
would be useful groundwork, but would not qualify variable-size containers.

Goose's long-distance return propagates hidden control state through ordinary
epilogues. It is not a promise of zero propagation work. Its implementation
also restricts reference-bearing long-distance returns more than the general
specification: the remaining limit is recorded in Appendix B. A7's canonical
Result/Option choice and defer cleanup remain authoritative. Resetting a memory
watermark cannot close a file or join a task. A nonlocal-return proposal must
cover cleanup, indirect callbacks, cross-module effects and foreign boundaries.
See [target checking](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/src/typecheck_calls.h) and
[nested-return fixtures](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/test/codegen/frame_return_from.goose).

Goose rejects escaping runtime function values and checks generics at concrete
instantiations. A7 supports mutable function bindings and saved targets, and has
explicit generic constraints. Copying Goose's restrictions would remove working
A7 behavior. Prefer behavior-preserving specialization of known callbacks; keep
runtime-selected calls. Bound specialization growth and preserve diagnostic
quality. No new recursive compiler traversal is needed. See
[the function-return rejection fixture](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/test/errors_tc/fnval_return.goose)
and [A7's specification](../../SPEC.md).

## Isolated workers still need a runtime and a lifecycle

Goose's flat types exclude references, slices and relative references at every
depth. Variable-sized contiguous values may still be flat. A compact graph with
relative links therefore is not automatically a legal queue element.

Workers have separate language storage and copied globals. This is not an OS
process isolation claim. The implementation uses native threads, heap-allocated
queue messages, mutexes and condition variables. Those mechanisms are hidden
from Goose source, not absent from the runtime. Its children may outlive their
parents; remaining workers end when main exits. See
[worker and queue implementation](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/src/runtime/runtime_threads.h) and
[flatness checks](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/src/typecheck_builtins.h).

A7's [structured-task proposal](../packets/P-CON-structured-tasks.md) instead
describes owned children, bounded channel instances and shutdown after cleanup.
It is still unapproved. Use Goose's checked isolation as input to that proposal,
without importing detached lifetimes or type-global queues by accident.
Two channels with the same payload type should have a deliberate identity rule.
Queue capacity, failed sends, resource ownership and cancellation need their
own observable contracts. A7 slice descriptors are not self-contained messages.

## What the benchmark numbers establish

At the pinned revision, the README's quoted ratios do not match its linked
generated results. The latter reports geometric speed means of 3.50/3.53 versus
idiomatic C++, 1.23/1.26 versus expert C++ and 1.12/1.19 versus the supplied safe
Rust implementations across two C toolchains. Its measurements are dated
October 10 and describe a Windows Ryzen 9950X3D machine. They do not establish
those ratios for the October 16 compiler revision or for A7.
See the [pinned results](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/bench/results.md).

The harness uses two warmups and the best of three whole-process times.
Memory is peak working set on Windows or peak RSS on POSIX. The aggregate
selects fastest and smallest rows separately. The implementation that wins time
need not be the one that wins memory. Some workloads lose against a comparator.

Source review found reporting limits worth avoiding: checksum-mismatched rows
can still contribute to displayed aggregates despite a final failing exit;
failed build/run rows can leave a reduced aggregate; merged partial results
lack per-row source/binary provenance. Only the last measured output is retained.
These are source observations, not newly executed failures.
See [the harness](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/bench/run_bench.py) and
[measurement support](https://github.com/aardappel/goose/blob/f6d31d0ef402dcbdc439d9abe50cebe37e5edd93/scripts/toolchain.py).

Keep A7 L38 unchanged: each equivalent required workload must meet the existing
median-time and peak-live-memory limit of 1.10 times reviewed C, including
bookkeeping. Preserve five warmups, thirty measured samples, raw distributions,
correctness on every sample, affinity and retained-work checks. Report RSS,
reserved/committed memory, copies, allocations, cleanup and compiler costs
separately. Deferring C export does not defer C benchmark controls.

## Why retain Zig

Zig already supports explicit alignment, byte-oriented memory access, C
interoperation and result-location semantics. These are useful implementation
tools, not a proof of A7 ownership or a blanket guarantee of zero-copy.
A variable-length record still needs an explicit layout and access strategy;
turning a declaration into a Zig packed struct does not create that strategy.
See the [Zig 0.16 reference](https://ziglang.org/documentation/0.16.0/#Result-Location-Semantics).

C can also express byte layouts, VM-backed regions and destination-passing calls.
Zig is the appropriate current choice because A7 already uses it and the user
selected it, not because the backend name settles safety or performance.
Retain explicit A7 checks where ReleaseFast would otherwise rely on unchecked
assumptions. No C emitter, TinyCC integration or backend replacement is proposed.

## Recommendation

Make data-stack placement, root inference, compact layouts and fresh-result
construction one coordinated candidate design. Evaluate it against the existing
memory candidates and real lifetime workloads. Develop relative-image formats,
static callback optimization and isolated message transfer as separate contracts
that can use that foundation.

Preserve A7's current deletion identity, list-sharing decision, Result/Option,
runtime function values, integer rules, iterative compiler and source-recursion
ban. Any intentional change gets a concrete before/after decision. The first
approval packet should cover the lifetime/placement rules and failure behavior,
with a bounded Zig prototype and independent measurements before a production
memory choice. The preparation sequence is recorded in the roadmap.
