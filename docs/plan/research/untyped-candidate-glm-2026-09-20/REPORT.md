# GLM-5.3 read-only review — frozen numeric prototype (review-candidate-2 / candidate-followup)

**Verdict: numerically sound within its tested scope.** I independently verified the rounding core, exact semantics, and exact-to-typed boundaries far beyond the report's matrix and found no wrong number. Two minor diagnostic/boundary findings (F1, F2) and one unverified flag (F3). The report does not overclaim; its scoping statements held up under checking. No language-approval inference is made.

## Independently verified correct

**Rounding (`ieee_bits`, exact_constants.py:81-111).** ~184,600 conversions (46,136 value families × 2 signs × 2 widths: random rationals up to ~130-bit components × 10^±340, powers of two ± tiny deltas across [-1080, 140], midpoints of every boundary family): 0 mismatches vs a floor/ceil distance-comparison reference, and 0 mismatches on the f64 subset vs CPython's correctly-rounded `int.__truediv__`. IEEE parameters, ties-to-even, subnormal quantization and the subnormal→normal transition (exact_constants.py:96,111), binade carry (104-106), and overflow classification are correct, including the exact overflow tie at both widths: 2^128−2^103 → reject for f32, 2^1024−2^970 → reject for f64, ±1 neighbors → max-finite/reject respectively. Three earlier "mismatches" during this review were bugs in my own reference, not the candidate.

**Exact semantics (`evaluate`, exact_constants.py:11-74).** 20/20 synthetic-AST cases: integer division truncates toward zero (−5/2 = −2), remainder takes the dividend's sign (−5%2 = −1, 4.0 % −2.0 = +0), floating quotient stays exact (1.0/3.0 = 1/3), all IEEE signed-zero rules for neg/+/−/×/÷/%, integer category preserved unless a floating operand participates. Shifts, bitwise, `and`/`or`, `~`, and calls return `None` (fallback, not approximate); division by zero raises the located error. `Fraction(raw_text)` accepts every float spelling the lexer produces (`5.`, `.5`, underscores, exponents) on Python 3.13 and 3.14 — checked, no crash path there.

**End-to-end through the frozen compiler** (compile-level, emitted bits inspected directly): f32 midpoint → 0x3F800000; double-rounding witness 1.0000000596046448 → 0x3F800001; 5e-324 → bit 1; −0.0 → sign bit preserved; max-finite accept / 1e100→f32 and 1e400→f64 reject at the operand span; `5/2`→f64 emits 2.0 bits, `5.0/2`→f64 emits 2.5 bits, `5.0/2`→i32 rejects fractional; `9007199254740993.0`→i64 emits the exact integer; forward-global `RATE :: 2.0` fits to `i32 = 2` with no first-use bias at the use; `i8 + 200` rejects (out of range for i8); `cast(u8, 256)` still rejected; global value cycle rejects with location; `(1.0/3.0)*3.0 == 1.0`, `0.1+0.2 == 0.3`, `2 == 2.0` fold true; typed comparison is *not* folded with untyped rules.

**Emission (backends/zig.py hunk).** `@as(fN, @bitCast(@as(uN, bits)))` from the already-selected bits — no decimal reparsing, no `comptime_float` intermediate; the report's emission claim is accurate.

**Evidence integrity.** Frozen helper SHA256 `b8365bb4…` matches final-sources and the reviewer oracle's recorded hash. final-results.json: 94 cases, 92 `passes_expectation: true` + 2 probes; 32 rejected — matches the report. Supplemental: 3 max-finite controls, all passing. selected-tests.json: 52 passed / 1 failed exactly as disclosed (no-recursion allowlist; `new_groups: []`). Reviewer's mixed-f32 midpoint probe prints `false` in Debug and ReleaseFast — native confirmation of direct f32 rounding in the mixed path. source.diff touches exactly the four claimed files; production `a7/` contains no exact-constant code (the working tree's other modifications predate/are unrelated to this candidate — the production zig.py diff has no bitCast/exact lines).

## Findings

**F1 — duplicated diagnostics for global zero division (minor, diagnostics quality).** `BAD :: 1.0 / 0.0` at global scope reports the identical located error **three times** (exit 6): once per fixed-point round in the pre-pass (type_checker.py hunk, `pending` loop), once in `visit_const_decl`'s own evaluation, once via `visit_expression`. Reproduced twice. Their matrix tested only local zero division (`zero_81/82`, which reports once), so the report's claim is accurate but this shape is untested and degraded.

**F2 — comparison-only acceptance of overflowing constants (boundary, defensible but undocumented).** `1e400 == 1e400` compiles and folds to `true` (both `y :=` and `if` forms) with no overflow error, because comparison folding (type_checker.py hunk at `visit_expression`) discards operands before any default materialization. Consistent with the packet (comparisons compare exact values; overflow rejection is a *fitting* rule), but any doc or report text saying "1e400 rejects" needs the "when fitted to a float destination" qualifier; the report's table doesn't carry it.

**F3 — skipped legacy typing on the mixed-integral path (flagged, not verified as harmful).** The mixed binary rule `return concrete` (type_checker.py hunk, ADD/SUB/MUL with exactly one exact operand and an integral peer) bypasses the remaining arithmetic-op typing block. My probes and their retained wrapping tests show correct behavior, but any legacy invariants living in the skipped block (e.g., proof annotations consumed by the safety pass) are skipped on this path; I did not run the full typed-wrapping matrix to bound this. Inference, not a confirmed defect.

## Limitations of this review

- I ran no Zig builds; native-output claims rest on the recorded evidence (Debug+ReleaseFast, host + Zig 0.16.0 only, as the report itself scopes) plus my compile-level bit-pattern checks. The controller's separate realnative IEEE runs remain the native authority.
- `evaluate`'s interaction surface (parenthesized chains, deeper DAGs, generic/pattern/index contexts) was tested at synthetic-AST level and via the report's matrix, not exhaustively; the report's own exclusion list ("no general exactness claim…") stands.
- The known blocker (no resource caps; unbounded bigint growth, O(n²) global fixed-point, whole-subtree dependency walks) is excluded per instructions; the report discloses it accurately.
- Advisory only; no source or docs were edited; no exhaustion or unsafe execution performed (all arithmetic bounded; largest values used were ~460-bit).
