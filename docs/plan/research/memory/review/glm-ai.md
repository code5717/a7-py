## Findings

### Blockers

1. **M11 has no extent-identification rules, so "training step" and "microbatch" are not implementable as written.** memory.md:505 names the extents but not how the compiler recognizes them in unannotated code. Audit-4 G-4 supplied the rules (session = extent of the value holding parameters; step = loop containing the parameter write; microbatch = extent containing `backward`; audit-4-tensors-autodiff.md:298–304) and revision 2 dropped them. Both external reviewers flag this (qwen.md M-7, kimi.md M-3). Without them, corpus 18 (accumulation across microbatches inside one step loop) and corpus 20 (OOM back-off) are undecidable: if inference equates the step with the innermost loop, `acc` is fine but recoverability attaches to the wrong extent; if it equates it with the outer loop, activations from all microbatches are retained and peak memory multiplies. Inference: this is the single load-bearing gap for AI memory.
2. **Contract item 7 is false for the AI path.** M20's deterministic runtime planner, its bounded cache, shrink-on-OOM, and compiler-inserted deep copies on escape/binding (contract items 4 and 8) are runtime work absent from §6 (memory.md:521–530). This is the AI-relevant half of Qwen B-1 (qwen.md:32–41) — the same defect class (B1) revision 2 claimed to have fixed. Until §6 gains rows for planning, cache eviction, shrink, and copies (each with a defined failure outcome under M2), the M16 safety-contract amendment would promise something the plan's own layer 7 contradicts.
3. **The native kernel bridge has no language surface and no gate.** M12 descriptors, corpus 12, kernel-bridge step 4 of the AI sequence, and all of Phase F's exit evidence depend on a native declaration syntax that does not exist (edge-case-audit.md:134–135) and on an approval gate that neither plan opens (qwen.md B-4, qwen.md:66–72). This is the critical path from the memory plan to L9/L10, and it is unscheduled.
4. **The closed rejection list (contract item 8) omits AI rejections the plan itself mandates.** A second `backward` on a consumed loss (M17), a gradient requested with respect to a rebound input (audit-4 EC4-11), and use of a resource after move/close are all rejections outside the nine classes (memory.md:75–86). Qwen B-2 shows the general problem (qwen.md:43–54); for the AI gates specifically, M17's use-after-move of a tape is the most likely diagnostic an ordinary training loop will hit. The list must be closed before M16 is amended.

### Major

5. **Tensor values-versus-views rules are still unwritten.** Revision 2 adopted M13 ("slices are temporary views; not stored or returned", memory.md:474) but not the operative tensor rules from audit 4: a view-producing call bound to a name is a value and the first write materializes a private copy with an M8 report (EC4-01); a reshape result is treated as may-alias with uniqueness never dependent on run-time strides (EC4-02); broadcast results are read-only descriptors with materialize-on-write (EC4-04); row assignment into a uniquely owned tensor is in place (EC4-38). Attention code is `transpose → reshape → matmul`; whether those rules exist decides whether ordinary transformer code incurs hidden O(size) copies — a direct L20 (C-like memory) risk and the mechanism behind Kimi B-2's concern (kimi.md:41–47).
6. **No complete hand-trace of either acceptance workload exists.** Audit 4 traced fragments (P1–P8); nobody has traced a full classifier step or decoder step through extents, saved values, liveness packing, and peak accounting, and no independently authored C/Zig baselines or margin-authorship procedure exist (Kimi B-2, kimi.md:41–47; Qwen B-5). The C-like claim for the two workloads is currently an assertion. Inference: this is the cheapest possible falsification of the riskiest modeling choice (tensors-as-values plus copy-when-unproven) and belongs in Phase A, not Phase F.
7. **M24 does not define data-phase load failure.** "Validate, then write in place" (memory.md:513) answers the header/shape case only; a read error after some parameters were overwritten leaves a half-old half-new model (audit-4 EC4-51 and §5 Q4; qwen.md M-8; kimi.md M-8). L10's checkpoint-recovery acceptance and validation V-14 (numerical-policy-glm.md:155) hang on this choice.
8. **M18's static rejection needs a may-save analysis that is nowhere specified.** With data-dependent branches or — the common case — one `forward` called from both a train loop (backward reachable) and an eval loop, saved-value facts must be joined over branches and call sites (audit-4 EC4-14, EC4-26). That depends on layer-1 sound joins (Phase B), which is fine, but the rule and its precision requirements should be part of M18 so its soundness premise is visible.
9. **The transactional optimizer-update rule is implied but unrecorded.** Phase F exit requires "skipped optimizer steps leave model values bit-identical" (memory.md:543), which requires audit-4 G-12/EC4-31's rule: no parameter write before the fused non-finite check and optimizer-workspace reservation both succeed. Likewise f32-master/f16-working-copy dual extents (EC4-30) and emulation widening temporaries (EC4-33, ai-frameworks-codex.md:243) are step-plan facts the plan should state. Minor to write, but they are exactly the memory-for-correctness rules mixed precision needs.
10. **G8 recipe decisions gate the memory design and are open.** Tied embeddings decide whether M19's parameter table is on the acceptance path (a user-visible concept, and Qwen m-7 already flags `detach`/`item()` vocabulary tension with contract 9, qwen.md:126); the optional KV cache decides whether M22 plus cached-vs-full equivalence testing is in v1 (ai-frameworks-codex.md:459 lists it as optional); the index dtype for token tensors is unnamed (audit-4 EC4-72 recommends `usize`); and no host memory budget exists to trigger M21's recomputation condition.

### Minor

11. M20 lacks sequence bucketing; per-length plans for lengths 1..2048 put pressure on the cache bound (audit-4 EC4-41).
12. Multi-loss `backward` or a persistent-tape form is not in M17's text (EC4-17); not needed for the two workloads, but aux losses are common.
13. M12's descriptor set omits the forward-to-backward workspace as a tape-owned saved value (audit-4 G-11/EC4-43; oneDNN max-pool/conv workspaces, numerical-policy-glm.md:46,99). Only needed if the oneDNN path is exercised.
14. M2's recoverability should record that native-library internal allocation (OpenBLAS build-time buffer pool that terminates the process, numerical-policy-glm.md:47) is outside the promise (audit-4 EC4-64).
15. Zero-size tensors (empty final batch) are unstated (EC4-48).
16. Positive: checked size/dimension arithmetic is already a §6 residual row covering G-10/EC4-46/47 (memory.md:529), and corpus 12's wording correctly implements G-7.

## Answer to the headline question

**Conditionally yes — this is inference, not a demonstrated result.** The two acceptance workloads sit exactly in the regime the plan targets: step-structured loops, mostly static shapes, a DAG of functional tensor ops, and value-granularity ownership. In that regime, extents + consume-on-`backward` (M17) + liveness-interval packing (layer 7) + uniqueness reuse (layer 6) can plausibly match a hand-written C/Zig trainer's peak memory and keep RSS flat across steps, with no allocator/arena/lifetime vocabulary in source; the rejections an ordinary user can hit are AI-semantics diagnostics (history escaping the step, mutating a saved value), not memory concepts, provided diagnostics are phrased that way. The conditions are the four blockers above plus two majors: the values-vs-views rules (5) must be written or attention code silently copies, and Phase A must contain full hand-traces plus independently authored baselines (6) or the C-like claim stays unfalsified. The unavoidable cost is over-retention inside a step and the `snapshot := model` copy (EC4-08) when a user asks for EMA/best-so-far — that is the honest tax the advisors predicted (synthesis.md:26–28). M21's posture (defer recomputation unless the decoder exceeds the host) is the right fallback and should be tied to a concrete memory budget decided in G8.

## Decisions the user must make

1. **M11 extent identification.** Adopt audit-4 G-4's structural rules (session = extent of the value holding parameters; step = loop containing the parameter write; microbatch = extent containing `backward`) or simplify to call/iteration/task/process + value-owned stores (Kimi M-3). Recommend: adopt G-4's rules; corpus 18 and 20 are already written against them.
2. **Contract 7 / §6 amendment.** Add runtime planner, plan-cache/eviction, arena shrink, and compiler-inserted copies to the residual-work table with defined outcomes, and restate item 7 as "no tracing, counting or scanning at run time". Recommend: adopt before M16.
3. **Native declaration surface.** Open a gate (new syntax, so it needs before/after examples under the approval rule) and schedule it as a Phase A decision and Phase F prerequisite. Recommend: yes — it is the critical path.
4. **Close the rejection list.** Reorganize into Qwen's four families and add second-`backward`/consumed-tape use, gradient-w.r.t-rebound-input, and resource-after-close. Recommend: adopt.
5. **Tensor values-vs-views rules.** Write EC4-01/02/04/38 into the plan under M11/M13 with M8 reporting of materialization copies. Recommend: adopt audit 4's wording.
6. **M24 partial-failure semantics.** In-place write with a compile-visible invalid state, or build-then-swap (2× peak). Recommend: in-place + mark-invalid, recorded as changing the L10 acceptance test.
7. **G8 recipe pins needed by the memory design.** Tied embeddings (recommend: untied for v1 acceptance, so M19's parameter table is not on the critical path), KV cache (recommend: defer; full-context generation for the small decoder, M22 + equivalence test later), token/index dtype (recommend: `usize`), precision policy (recommend: f32-qualified first, f16/bf16 as a separate qualification), and the host memory budget that arms M21.
8. **Phase A evidence.** Require full hand-traces of both workload steps and independently authored, toolchain-pinned baselines before margins are set. Recommend: yes.
9. **Rerun the nine GLM reviews** (AI, security, contract at minimum) before M16 and Phase F. Recommend: yes; L12 currently has no evidence behind these gates.
