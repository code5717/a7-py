# Lobster lessons for A7

Reviewed 2026-10-17. This is documentation research using the official
[Lobster homepage](https://strlen.com/lobster/) and linked manuals. No Lobster
compiler or benchmark was executed. These moving pages are not a pinned source
review. Recommendations below are A7 design judgments, not adopted behavior.

## Automatic memory with a runtime fallback

Lobster combines inferred borrowing with runtime reference counting. A new
allocation gets an owner; additional ownership can require a count increment.
A borrowed local can become an owner when its original storage is overwritten.
The manual also describes ownership-based function specialization. The reported
95% elimination of count operations is an author measurement, not a universal
guarantee. Its optional strict single-owner mode is marked unimplemented in
that document. See [memory management](https://aardappel.github.io/lobster/memory_management.html).

That manual explicitly identifies an analysis gap involving a reassigned owning
alias and writes through that alias while another field is borrowed. This makes
its examples useful adversarial inputs, rather than evidence that A7 can assume
aliases are harmless. Cycle reporting at exit also leaves reclamation work to
the programmer; it does not satisfy A7's automatic-memory goal by itself.

The manuals disagree on `f(v[0], v.pop())`: the memory guide calls it an error,
while the [language specification](https://aardappel.github.io/lobster/language_spec.html#borrowing)
says the borrower becomes an owner and the call is accepted. This study does
not resolve that behavior through execution. Use a pinned compiler and regression
test before borrowing that exact rule. The specification also names untracked
aliases from function results, stored objects and copied reference fields, plus
aliases assigned later in a loop. Those are direct candidates for A7's safety
test matrix, not acceptable omissions from A7's contract.

A7 experiment: compare unoptimized RC with inferred borrowing on the existing
memory workloads. Count retains, releases, allocations, copied bytes and peak
live memory. Include saved aliases, overwrite through another owner, vector
removal, call-argument evaluation order and deferred cleanup. Keep the adopted
per-workload C limits and cyclic workload. Compare against the arena prototype;
do not select either production mechanism from an operation-count reduction.

## Specialization and proof boundaries

Lobster combines inference, specialization by argument types and call-order
checking. Its documentation warns that fewer annotations can make error origins
harder to locate. It also permits compile-time type conditions to discard a
branch before type checking it. See the
[type system](https://aardappel.github.io/lobster/type_checker.html).

For A7, expose the call context that caused a proof failure. Record the relevant
argument identity, active branch and invalidating write. Measure specialization
count, compile time and output size alongside runtime speed.

Do not adopt Lobster's discarded-branch typing rule implicitly. A7's current
missing-proof codegen failures need an explicit contract between safety and
lowering. A body omitted after a proof of impossibility must preserve condition
effects and remain distinct from a body that was never analyzed. This is a
compiler-correctness requirement, not permission to skip ordinary type errors.

## Small values and callbacks

The reference distinguishes inline copied structs from heap classes. Copying a
struct can still share its referenced objects; inline storage does not imply a
deep copy or worker isolation. See the
[value semantics](https://aardappel.github.io/lobster/language_spec.html#value-and-reference-semantics).
Generic
function-value arguments can be inlined; function values referring to outer
variables are non-escaping. The reference describes both compile-time checks
and a runtime error for invalid free-variable access, so this is not evidence
of universally static escape checking. That restriction limits callback use. Named
nonlocal returns are another separate language facility. See the
[language reference](https://aardappel.github.io/lobster/language_reference.html).

For A7, measure small inline records and specialized map/filter loops against
handwritten loops through Zig. Include construction and copy counts. Any new
callback escape rule needs a proposal with accepted and rejected examples.
Nonlocal returns need cleanup-order and cross-frame lifetime rules before an
approval request. Keep the existing Result/Option decisions and recursion ban.

## String construction without temporary strings

The [memory manual](https://aardappel.github.io/lobster/memory_management.html)
describes appending into a uniquely owned string when capacity permits. Shared
strings are copied. Concatenation pieces can be written directly into the
destination without constructing the combined right-hand string first. All
operands are evaluated before appending; self-references retain their old value.
The manual separately describes byte-buffer writes as mutating shared storage.
These operations therefore need distinct alias contracts.

A7 experiment: compare repeated concatenation with destination construction on
the text workload. Measure allocations and copied bytes. Include a saved alias,
self-append, a substring of the destination and an operand with side effects.
Require identical output and evaluation order before comparing speed. Any
change to observable string sharing needs its own approval; this research does
not establish A7 string mutation semantics.

## Worker isolation

Lobster describes separate VM state per worker and copied messages through a
tuple space. Its reference labels multithreading as early-stage. This provides
a comparison for A7's concurrency proposal, not evidence of A7 concurrency or
GPU execution. See the
[threading section](https://aardappel.github.io/lobster/language_reference.html#multi-threading).

A7 should specify queue ownership, bounded capacity, cancellation, worker errors
and joining before selecting an implementation. Measure serialization and copy
costs with large messages. Avoid assuming Lobster's copied object messages have
Goose's flat representation or that either removes all synchronization inside
the runtime. GPU execution remains deferred under L75.

## Fit with current decisions

Lobster offers an RC-based comparison to Goose's data-stack direction. Both
inform experiments; neither replaces A7's measured memory decision process.
Keep Zig as the backend. C/C++ export, indentation syntax, class inheritance,
implicit numeric conversions and Lobster's runtime are not selected here.
The [decision ledger](../decisions.md) remains authoritative. Implementation
work and unresolved requirements remain in [Status](../../STATUS.md) and the
[delivery roadmap](../delivery-roadmap.md).
