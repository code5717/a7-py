# Structured tasks and bounded channels

Status: unapproved decision draft. No API, syntax extension, scheduler or memory
mechanism in this packet is implemented or selected. The unresolved fields below
prevent treating this packet as authorization to implement the whole interface.

## Current behavior and authority

The [current compiler probes](../../../tmp/v1-completion-2026-10-07/concurrency-current-probe/REPORT.md)
use frozen `de578138` and preserve all 1,664 source hashes and modes. A sequential
`work(41)` passes semantic checking and Zig emission. Importing `std/tasks` or
`std/channels` exits 3 at 1:1 with `ImportError` in both modes. No native program
was built or run. The evidence does not establish concurrent execution.

[Decisions L19, L21, L37-L40 and L73](../decisions.md) constrain memory burden,
checked execution, independence and the required full V1 result. They do not
approve this interface. L73 requires real concurrency; restricting V1 permanently
to scalar tasks would not satisfy it. L38's cost requirement includes runtime
bookkeeping. GPU experiment deferral does not remove CPU concurrency work.

This draft develops the [transition proposal](../research/concurrency-transitions.md)
and [package F research](../research/language-features-codex.md). The
[prerequisite inventory](../../../tmp/v1-completion-2026-10-07/concurrency-design-prerequisites/REPORT.md)
separates adopted constraints from historical memory recommendations. In
particular, last-sender channel closure in package F is an alternative to the
explicit close authority proposed here.

## Proposed interface

Use library calls rather than new spawn or await keywords. A group owns every
started child until child cleanup completes. No detach operation exists. Handles
cannot escape the group's lifetime. The following are interface descriptions,
not accepted A7 declarations. `$A`, `$T` and `$E` denote argument, result and
application-error types; capacity and task ordinals use `usize`.

L68 adopts U2/U3: fallible operations use canonical `Result`/`Option`, with
compiler-provided type names. U1/U4/U5 select module free functions and explicit
`std/` imports. Those choices are settled; the operation-specific types below
remain proposed. `Result(S,E)` has `.ok(S)` and `.err(E)`;
`Option(T)` has `.some(T)` and `.none`. Successful operations without useful data
return `true`, following the existing `Result(bool,E)` convention rather than
assuming a new unit type.

| Operation | Proposed result and ownership |
|---|---|
| `tasks.open()` | `Result(Group, CreateError)`; error creates no group |
| `tasks.start(group, work, argument)` | `Result(Job(T,E), StartError(A))`; `.cancelled(A)` or `.failed(StartFailure(A))` inside the error retains the evaluated argument |
| `tasks.cancel(group)` | Idempotent request; no allocation or completion claim |
| `tasks.check_cancelled(context)` | Boolean observation of the current request |
| `tasks.join(job)` | `Result(T, JoinError(E))`; error variants distinguish application failure, child cancellation, child runtime failure, interruption and wait failure |
| `tasks.finish(group)` | `Result(bool, FinishReport)` after mandatory shutdown and all child cleanup; consumes the group on either outcome |
| `channels.bounded(group, capacity, element_type)` | `Result(Channel(T), ChannelCreateError)`; errors distinguish invalid capacity from resource failure |
| `channels.send(sender, value)` | `Result(bool, SendError(T))`; errors `.closed(T)`, `.cancelled(T)` and `.failed(SendFailure(T))` retain the unsent payload |
| `channels.receive(receiver)` | `Result(Option(T), ReceiveError)`; `.some(T)` transfers a value, `.none` means closed and empty; errors distinguish cancellation and runtime failure |
| `channels.close(closer)` | Idempotent ordinary close; no allocation, cancellation or queue discard |

`work` receives a group-supplied cancellation context and one argument, which may
be a record. It returns `Result(T, TaskError(E))`. The proposed task error union
contains `.application(E)` and `.cancelled(bool)`; the cancellation marker is
`true`. For the scalar examples, `tasks.I32Error` is this union specialized to a
copyable application error code. Child runtime failures are generated by the
runtime, separately from callback application errors.

`JoinError(E)` contains `.application(E)`, `.cancelled(bool)`,
`.runtime_failed(TaskRuntimeError)`, `.interrupted(bool)` and
`.wait_failed(WaitError)`. Success and the first three error variants consume a
terminal outcome. Interruption and wait failure retain it. The examples use bare
error tags when no payload inspection is needed; all bound error wrappers in
these scalar/record illustrations contain only copyable fields.

Starting evaluates the callable and argument once before transfer. Failure to
start does not undo their effects. Transfer commits only when the runtime has
accepted responsibility for running or cleaning up the child.

A join interrupted by caller cancellation retains the job and its outcome for
another join or mandatory group shutdown. A recoverable join infrastructure
failure returns `wait_failed` and retains them. A terminal child runtime
failure returns `runtime_failed` after cleanup and consumes that outcome.
Neither failure licenses releasing storage still accessed by a live child.
Repeated consumption of a terminal outcome is a semantic error where provable;
otherwise a checked error must survive release compilation.

`finish` stops starts, requests cancellation and waits. It does not require every
job to have been explicitly joined. An already consumed application failure is
not reported again. The proposed report retains all unconsumed application and
runtime failures in task-start order, plus stop/cleanup failures. Cancellation
alone is not a failure. Successful unconsumed results are released after joins.
Report storage must not require an allocation that can fail while reporting an
allocation failure. Its bounded representation remains an explicit design field.

## A7-shaped examples

Every block below is a complete proposed program, not a runnable current example.
Imports, module types and operations are future API names. They use existing
function, record, tagged-union and match grammar from SPEC sections 4, 5.2 and
7.4. The scalar examples use a proposed `start_i32` adapter and copyable handle
capabilities so they can show all control paths without inventing move-pattern
syntax. These adapters illustrate the general interface; they are not a proposed
limit on payload types. Capability copying never duplicates ownership of a job or
group. Its checked single-consumption and lifetime rules still need representation.

Proposed scalar success prints `42`, unless resource creation or execution fails,
in which case the program prints the selected failure. Finishing always follows
an opened group, including unsuccessful starts and interrupted joins.

```a7
io :: import "std/io"
tasks :: import "std/tasks"

work :: fn(context: tasks.Context, value: i32) Result(i32, tasks.I32Error) {
    ret Result(i32, tasks.I32Error){ok: value + 1}
}

main :: fn() {
    match tasks.open() {
        case .ok(group): {
            match tasks.start_i32(group, work, 41) {
                case .ok(job): {
                    match tasks.join(job) {
                        case .ok(value): io.println(value)
                        case .err(error): {
                            match error {
                                case .application: io.println("application failure")
                                case .cancelled: io.println("child cancelled")
                                case .interrupted: io.println("join interrupted")
                                case .runtime_failed: io.println("child runtime failure")
                                case .wait_failed: io.println("join wait failure")
                            }
                        }
                    }
                }
                case .err(error): {
                    match error {
                        case .cancelled: io.println("start cancelled")
                        case .failed: io.println("start failure")
                    }
                }
            }
            match tasks.finish(group) {
                case .ok: {}
                case .err: io.println("finish failure")
            }
        }
        case .err: io.println("create failure")
    }
}
```

Proposed cancellation has a deliberate deterministic boundary: cancellation occurs
before the start attempt. No child is accepted, and the returned scalar argument
is `7`. This example does not promise that cancellation wins a race against an
already running child. The worker shows an explicit cooperative observation.

```a7
io :: import "std/io"
tasks :: import "std/tasks"

work :: fn(context: tasks.Context, value: i32) Result(i32, tasks.I32Error) {
    if tasks.check_cancelled(context) {
        ret Result(i32, tasks.I32Error){err: tasks.I32Error{cancelled: true}}
    }
    ret Result(i32, tasks.I32Error){ok: value}
}

main :: fn() {
    match tasks.open() {
        case .ok(group): {
            tasks.cancel(group)
            match tasks.start_i32(group, work, 7) {
                case .err(error): {
                    match error {
                        case .cancelled(value): io.println(value)
                        case .failed: io.println("start failure")
                    }
                }
                case .ok: io.println("unexpected accepted start")
            }
            match tasks.finish(group) {
                case .ok: {}
                case .err: io.println("finish failure")
            }
        }
        case .err: io.println("create failure")
    }
}
```

The channel example carries a record, not an `i32` payload. Proposed factory
`bounded(group, capacity, Message)` uses a type argument; that library calling
convention needs validation against generic registration. With successful
creation/send, the program prints `9` and then `closed`. Capacity is one, so this
single-threaded illustration does not block. Parallel producer/consumer tests are
required separately. Ordinary close drains the already committed message.

```a7
io :: import "std/io"
tasks :: import "std/tasks"
channels :: import "std/channels"

Message :: struct {
    sequence: usize,
    value: f64,
}

main :: fn() {
    match tasks.open() {
        case .ok(group): {
            match channels.bounded(group, 1, Message) {
                case .ok(channel): {
                    match channels.send(channel.sender, Message{sequence: 9, value: 2.5}) {
                        case .ok: {}
                        case .err(error): {
                            match error {
                                case .closed: io.println("send closed")
                                case .cancelled: io.println("send cancelled")
                                case .failed: io.println("send failure")
                            }
                        }
                    }
                    channels.close(channel.closer)
                    match channels.receive(channel.receiver) {
                        case .ok(item): {
                            match item {
                                case .some(message): io.println(message.sequence)
                                case .none: io.println("empty")
                            }
                        }
                        case .err(error): {
                            match error {
                                case .cancelled: io.println("receive cancelled")
                                case .failed: io.println("receive failure")
                            }
                        }
                    }
                    match channels.receive(channel.receiver) {
                        case .ok(item): {
                            match item {
                                case .none: io.println("closed")
                                case .some: io.println("unexpected value")
                            }
                        }
                        case .err(error): {
                            match error {
                                case .cancelled: io.println("receive cancelled")
                                case .failed: io.println("receive failure")
                            }
                        }
                    }
                }
                case .err(error): {
                    match error {
                        case .invalid_capacity: io.println("invalid capacity")
                        case .failed: io.println("channel create failure")
                    }
                }
            }
            match tasks.finish(group) {
                case .ok: {}
                case .err: io.println("finish failure")
            }
        }
        case .err: io.println("create failure")
    }
}
```

validation, if recorded later, cannot validate these APIs or ownership rules.

## General payloads and channel ownership

U6 already selects shared list identity: assignment and returning a list copy the
shared handle; `list.copy` makes an independent list, and users do not free lists
by hand. Passing a list to a task therefore cannot imply unique ownership or
permission for concurrent mutation. Transferability and sharing checks must
preserve this adopted identity while constraining concurrent access. U6's
`push`/`try_push` allocation-failure policy is also settled; it does not select
cleanup behavior for arbitrary resources or channel closure.

The intended contract includes records, owned buffers, application errors and
returned resources. Proposed `Job(Buffer, DecodeError)` and
`Channel(Message(Buffer))` must transfer ownership without copying an owning
payload. Failed send/start returns the original payload to the caller. Bare tag
matching cannot silently discard it; discard requires defined cleanup.

Current SPEC 5.2 permits only copyable tagged-union payload binding. It rejects
binding a string payload. More precisely, the current checker rejects payload
types containing strings by value. It stops at refs, pointers and slices.
The [current payload probes](../../../tmp/v1-completion-2026-10-07/union-payload-current-probe/REPORT.md)
confirm accepted ref and slice captures and repeated scalar matching, alongside
rejected string and string-record captures. This classifier does not establish
ownership or cross-task transferability. This packet therefore does not present
`.ok(buffer)` or `.closed(buffer)` as existing syntax. A move extraction
operation or an approved result-consumption rule is required for general payloads.
Likewise, generic function-result inference and public construction/access of
library handle records must be qualified before the schematic API becomes usable.

A channel has separate sender, receiver and close capabilities. The proposed
creator owns close authority and may explicitly transfer it. Dropping a sender
does not close the channel. Endpoint duplication, if offered, duplicates only the
permission and preserves the group's lifetime. It cannot duplicate close authority
implicitly. Close stops new send commits, wakes waiters and allows queued FIFO
messages to drain. FIFO means enqueue commit order, not source order among tasks.

Send/receive cancellation is resolved at the ownership commit point. Before
commit, a cancelled send returns its payload. After enqueue, the queue owns it and
send reports success even if cancellation arrives. A committed receive owns its
payload even if cancellation arrives next. Close/cancellation races choose the
first applicable event before commit; exactly one owner remains. Group shutdown
cancels waits rather than promising to drain every queue. Remaining queued values
are released only after children stop accessing them.

## Cleanup, native calls and sharing

Proposed shutdown orders explicit pre-join stop actions, shielded mandatory joins,
then queued payload/result disposal and release of parent-borrowed storage.
Ordinary A7 defers retain their existing reverse order within their applicable
scope. This proposal does not move arbitrary parent defers before joins. An early
return must still perform group shutdown before releasing dependent parent values.
How an unobserved finish failure combines with a pending return is unresolved.

Stop actions may signal external producers but cannot reclaim or mutate storage
borrowed by a child. Closing a borrowed descriptor requires a declared concurrent
shutdown contract. Stop failure is recorded and does not bypass joins. Child
cleanup completes before the child becomes terminal. It cannot depend on disposal
of queued values or unconsumed results scheduled after that same join. Returned
resources retain their dependencies; a result borrowing expiring child storage
cannot be transferred without a valid lifetime rule.

A mandatory join ignores cancellation as a reason to abandon its children. It may
service only declared native completion callbacks. A native descriptor must state
callback thread affinity, progress/event-loop dependencies, lock requirements,
retained storage and stop-action effects. Callback service cannot start new group
work or enter partially cleaned parent state. Unknown requirements prevent task
admission until described; existing sequential calls keep their current behavior.
Shielding prevents premature release, not deadlock. Neither these rules nor
ownership checking prove termination of arbitrary native calls or wait cycles.

Read-only parent sharing lasts until the last accessing child finishes. Concurrent
conflicting writes require a proof of disjoint access or an approved synchronization
operation. The same rule covers globals and indirect reachable storage. Unknown
effects remain sequential; an explicit task start with unproved sharing must be
rejected or use a separately approved checked mechanism. This packet does not
select a collector, reference-count scheme, allocator or general alias policy.

CPU cancellation is cooperative. Cancellable channel waits and user joins observe
requests. CPU loops require explicit `check_cancelled` observations under this
proposal; no poll interval or latency bound is invented. Mandatory joins still
wait for a noncooperative CPU task. Whether V1 requires compiler-inserted polls is
an alternative needing a cost and responsiveness decision. Native cancellation
requires its declared protocol; a task can remain live until an uninterruptible
native call returns.

## Alternatives and compatibility

| Choice | Proposed direction | Alternative and consequence |
|---|---|---|
| Surface | Library operations, no new keywords | Dedicated task syntax could express lexical lifetime directly, but needs grammar approval |
| Lifetime | Structured group, no detach | Unstructured tasks need a separate process-lifetime and error-observation contract |
| Closure | Explicit close authority | Last-sender close needs endpoint counting and a distinct closure race contract |
| Capacity | Positive explicit bound | Zero-capacity rendezvous and unbounded channels require separate commit/resource rules |
| Runtime | Unselected | OS threads, CPU pool or cooperative tasks each need blocking/progress experiments |
| Cancellation | Explicit CPU checks | Inserted polls change runtime cost and require a stated scheduling policy |
| Result extraction | Unresolved for owning payloads | Move matching or consuming library extraction must preserve failed-transfer ownership |

Existing sequential programs and direct math-call formatting are unchanged by
this proposal. New imports would change the observed exit-3 cases into usable
library calls. New task calls introduce explicit concurrency and resource failures;
no existing sequential call is silently scheduled in parallel. Restrictions apply
to values admitted to tasks/channels, not a new blanket rejection of sequential
mutable globals. Current source recursion remains banned.

## Acceptance and unresolved decisions

Approval must resolve these fields before implementation is called complete:

1. Group/handle lifetime representation, owning result extraction and the generic
   signature/visibility rules required by the proposed interface.
2. Automatic early-exit shutdown placement and unobserved finish-failure delivery,
   including pending returns and multiple cleanup failures.
3. Close-capability transfer/duplication, endpoint lifetime and failure-report
   storage when allocation is unavailable.
4. Sharing/effect admission and native callback/stop descriptors, including how
   the compiler represents obligations without selecting a memory mechanism here.
5. CPU cancellation policy and the runtime model used to qualify blocking and
   real parallel CPU work. A prototype must not become an implicit API decision.

Required acceptance evidence after approval includes:

- Real native CPU work in at least two children, with event/barrier evidence of
  overlapping execution and correct independently computed results. No sleep-only
  demonstration, mocked scheduler or sequential source-emission proxy.
- Each create/start failure before commit retains its evaluated argument once;
  successful start transfers it once. Inject failures at named resource boundaries.
- Successful, failed and cancelled joins; interrupted joins retain ownership;
  completion winning cancellation preserves the result. Finish reports all
  unconsumed failures in the selected order.
- Cancellation racing enqueue/dequeue/close, blocked send on a full queue, blocked
  receive, close with queued messages and close-empty EOF. Count payload cleanup
  and prove no loss, duplicate ownership or second consumption.
- Parent early return, child defer failure, producer stop failure and callback
  progress on the required thread. Observe child cleanup before parent storage
  release and test the known cleanup-dependency deadlock counterexamples.
- Read-only sharing, distinct writable regions and rejected conflicting global or
  captured writes, including aliases through aggregates and native retention.
- General owning payloads and error/result types, not only the scalar adapters.
  Failed send and returned-resource cleanup must exercise real lifetimes.
- Cooperative CPU cancellation and declared uninterruptible native work, reporting
  measured behavior without claiming arbitrary deadlock freedom or a latency bound.
- Debug, ReleaseSafe and ReleaseFast native qualification, package-installed use,
  and the adopted runtime/memory comparison including bookkeeping costs.

This packet supplies proposed transitions and examples for decision. It does not
close the memory mechanism, general result-consumption or concurrency milestone.
